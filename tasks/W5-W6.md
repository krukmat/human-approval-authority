# W5/W6 — Hardware Authenticator Subplan

These waves are blocked until W4-T06 records PASS.

## W5 — POC

- **W5-T01:** freeze BOM + XIAO ESP32-S3 firmware scaffold; USB only.
- **W5-T02:** verify HAA-signed challenge package on-device before any display/action.
- **W5-T03:** deterministic OLED renderer + physical reject control; unsupported profiles fail closed.
- **W5-T04:** FPC2534 enrollment/match remains local; no biometric material reaches host/HAA.
- **W5-T05:** device identity/evidence; enforce verify → display → match → sign in normal firmware.
- **W5-T06:** HAA hardware EvidenceVerifier adapter with no core semantic changes.
- **W5-T07:** repeat the same agent/executor scenario used for Apple and confirm identical domain semantics.

## W6 — Hardening

- **W6-T01:** threat review from real POC.
- **W6-T02:** Secure Boot, signed firmware and production debug policy; maintain separate dev-device procedure.
- **W6-T03:** integrate ATECC608C-class key storage if the threat review justifies it.
- **W6-T04:** revocation, re-enrollment and anti-replay/counter behavior.
- **W6-T05:** authenticated firmware update path with recovery/rollback policy.
- **W6-T06:** adversarial acceptance gate. Do not claim FIDO, legal-signature or certified tamper resistance.

The firmware is explicitly part of the trusted computing base because a secure element cannot independently prove that the fingerprint sensor matched before the MCU requested a signature.
