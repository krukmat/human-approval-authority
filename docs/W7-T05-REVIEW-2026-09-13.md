## HAA-REV-001 — retired authority key can mint fresh detached grants

Original severity: `BLOCKING`

Disposition: **RESOLVED — INDEPENDENTLY VERIFIED**

Remediation:

- live `ExecutionGrant` verification requires the referenced authority key to be `ACTIVE`;
- RETIRED keys remain available for historical verification, but cannot authorize live detached execution;
- verifier checks timestamp ordering, future issuance, key-created-at boundary and maximum execution-grant TTL;
- regression coverage reproduces a grant minted after retirement with the retained private key and requires `AUTHORITY_KEY_NOT_ACTIVE`.

Security rule:

```text
Historical verification may retain RETIRED public keys.
Live ExecutionGrant authority requires ACTIVE key status.
```

## HAA-REV-002 — authenticator revocation did not invalidate unconsumed approval

Original severity: `P1`

Disposition: **RESOLVED — INDEPENDENTLY VERIFIED**

Before issuing/consuming a new grant, `authorizeAndConsume` resolves the approval receipt's authenticator and requires it to remain ACTIVE. If it is missing/revoked, HAA materializes `APPROVED -> REVOKED`, writes a `REVOKED` audit event with `reason=AUTHENTICATOR_REVOKED`, and denies new execution authority. Existing same-execution-ID idempotency after a prior consume remains intact.
